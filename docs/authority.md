# Behavioral authority

Haskell behavior is authoritative during construction of this suite, as selected by the user on 2026-11-02. The borrowed OpenAPI document is a useful inventory and schema source; observed, reproducible Haskell behavior resolves discrepancies. `fixtures/api/openapi.yaml` remains byte-for-byte pinned. `fixtures/api/haskell-corrections.json` applies individual edits before YAML alias expansion, checks the original SHA-256 and requires each edit to match exactly once. The rationale and observations are in `docs/known-spec-defects.md`.

Reports bind to a SHA-256 fingerprint of executable assertions, the original API, corrections, required catalogue and all shipped HTTP/vector corpora. Reports produced before a change cannot establish conformance for the changed suite. Historical reports are retained as historical evidence; rerun affected reference validation rather than editing their results.

The future authoritative specification will be generated from this suite. It must include the effective API schemas, exact HTTP expectations and comparison exceptions, adapter vector contracts and independent provenance, catalogue, and actual evidence of execution. During construction, generated specifications must identify themselves as drafts and enumerate unresolved obligations. Completing a bounded catalogue does not prove mathematical equivalence for all possible inputs or environments. A change of authority requires an explicit reviewed specification version; this harness must never silently treat candidate outputs as normative.

Runtime files must also match the registered frozen inputs. Cases and vectors are compared after typed deserialization, so JSON formatting does not affect eligibility. A modified expectation retaining a committed ID is marked in `unregistered_inputs`; the gate rejects such reports even when their development assertions pass. Subsetting registered vectors by operation is permitted for development, while every omitted mandatory case remains a coverage gap.
