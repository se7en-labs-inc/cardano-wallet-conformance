# Checkpoint restoration proof in progress

T087 now has a fresh28/28 passing live component; see [the retained evidence](../evidence/reference-checkpoint-restoration/README.md). A process restart and final balance equality do not prove checkpoint reuse. The required live profile will keep the wallet offline while the same native chain advances and receives another payment, then observe a real accepted non-origin intersection from the restarted client and verify full catch-up, preserved state and native accounting.

The passive Rust observer retains connection IDs, full public chain points/tips and explicit parsing errors. It does not retain blocks or transaction payloads, modify forwarded bytes, manufacture node responses or award coverage on its own. It bounds connections, events and buffers, matches intersection responses to actually offered full points on the same connection, and detects truncated messages. The default Unix socket fault-control mode still interprets no bytes; observation is explicit. A forwarding regression sends over1MiB of arbitrary binary bytes through the observed relay and requires exact echo/half-close behavior even after parsing fails.
