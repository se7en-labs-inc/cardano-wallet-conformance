Still required before calling this exhaustive:

- A complete positive workflow and all error/status/boundary variants for each API operation, including shared and hardware/watch-only wallets, Byron spending/migration, staking, pool/metadata services, governance, mint/burn and collateral.
- Complete Cardano extended signing, second factors, hardware variants, encrypted keys and passphrase migration corpora; invalid/noncanonical keys, paths, signatures, addresses and CBOR.
- Exact independently captured seeded Haskell selection-strategy vectors plus randomized selection distribution/quality requirements where part of the compatibility contract.
- Fee/min-UTxO, serialization, metadata/native/Plutus script, validity interval, certificates and era-boundary vectors.
- Real rollback/fork, interrupted restoration, disconnect/reconnect, restart/resubmission, expiry, concurrent spend and durable-state scenarios.
- An executable reference domain adapter where HTTP and published vectors cannot expose internals, plus implementation of the same adapter against each candidate wallet.
- Validation of the complete corpus against the exact pinned Haskell source revision and the eventual candidate. Release binaries can validate harness workflows but must be recorded under their actual revision.

A requirements catalogue is a map of obligations, not a claim those tests already exist. Neither endpoint count nor the number of cryptographic vectors establishes 100% semantic compatibility for untested inputs. Test results can certify a pinned, explicitly bounded contract; mathematical all-input equivalence needs additional proof.
