# Owned process harness checks

Five targeted harness tests pass, including real child crash/restart with persisted filesystem state, old-child reaping, cleanup on drop, refusal of existing workspaces/ambiguous database placeholders, and refusal to restart a changed executable while preserving the live owned child. The fixture test runs directly as one of these five tests and serves as the foreground subprocess for the lifecycle checks. Private directory/log permissions are verified on Unix. Cargo fmt and all-target/all-feature Clippy pass.

These are process-control tests, not cardano-wallet conformance results. No mandatory case IDs or live evidence are bound. The control is not yet wired into a wallet lifecycle profile. The already-preserved many-input parser regression remains unresolved; the full cargo test/Nix package checks were not rerun as passing. No wallet or cluster services were launched for these checks.

The JSON launch manifest has executable (absolute path), arguments (string array), and optional environment (string map), with unknown fields rejected. Exactly one argument or environment value must be the complete string {database}. WalletProcess::start creates a new absolute workspace and private database, records executable identity and launches a foreground child directly. crash_restart preserves database/arguments, verifies identity, kills/reaps the owned child and relaunches. No supplied PID can be adopted. Per-generation stdout/stderr logs and the database remain private local artifacts after cleanup. Children must stay in the foreground and must not daemonize; this control does not supervise grandchildren or provide node partition/rollback orchestration.
